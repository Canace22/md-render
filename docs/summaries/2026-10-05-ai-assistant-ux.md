# AI 助手交互优化

日期：2026-10-05

## 结果

AI 助手这轮交互优化已按 `docs/ai-assistant-ux-plan.md` 完成。它现在既能作为聊天助手找灵感，也能在写作模式下改稿；选区润色、外部资料读取、平台稿生成和会话管理都有明确入口，并保留原稿与安全边界。

## 完成内容

| 阶段 | 用户能看到的变化 | 关键边界 |
|------|------------------|----------|
| P0 基础响应 | AI 回复可流式显示；运行中继续发送会排队；失败可重试并按需打开设置 | 停止后丢弃迟到结果；本机 agent 保持原通道 |
| P1 选区润色 | 选中文字后可润色、改口语/正式、精简，并在对比卡里接受、放弃或再来一版 | 接受前不写回；只替换原选区并进入撤销栈 |
| P2 找灵感 | 会话分聊天/写作模式；可读公开 URL、拖入常见文档并把回复记到「灵感」 | 聊天模式不带当前稿件和写工具；网页防 SSRF；图片不假装识别 |
| P3 准备发布 | 一次选择多个平台，可选先审稿；按平台查看标题、摘要、标签、正文，复制或保存平台稿 | 生成只是预览；明确保存后才创建带来源关系的派生资产 |
| P4 面板精简 | 四个常驻 tab 改成标题下拉与齿轮菜单；欢迎页按模式区分；面板可拖拽调宽 | portal 随面板关闭；宽度本地容错保存；skill 入口由 registry 驱动 |

## 架构与安全取舍

- AI 请求继续遵守 Renderer → IPC → Main → ai-proxy 的边界，Renderer 不直接访问系统资源。
- 聊天、写作和发布流程共享现有 agent 引擎，但通过模式、工具白名单和只读本机 agent 会话隔离副作用。
- URL 与附件正文按不可信外部资料处理；网页读取沿用地址校验、DNS 固定和重定向限制。
- 平台内容默认生成新资产并记录来源，不覆盖原稿；标签和派生关系在同一次保存中写入。
- `selection-toolbar` 成为正式 skill 入口，并由选区工具栏实际消费，避免配置存在但界面不可达。

## 建议人工验收的 10 个 case

1. API 来源连续流式回复时，文字只更新同一条消息；停止后不再回流迟到内容。
2. 运行中连续发送两条消息，显示排队数量，并可取消未开始的消息。
3. 制造连接失败后，错误消息可重试，连接类错误能打开设置。
4. 选区润色接受后只替换原范围，撤销能恢复；放弃不会改稿。
5. Daily 编辑器不出现选区 AI 按钮，普通稿件只显示 registry 允许的按钮。
6. 聊天模式提问不读取或修改当前稿件；切到写作模式后相关能力恢复。
7. 公网 URL 能读取正文；本机、内网、重定向到内网的地址被拒绝。
8. 拖入 md、txt、pdf、docx 后能发送文本；图片明确提示当前不能识图。
9. 多平台生成后各 tab 内容互不串位；复制、公众号预览和显式保存都对应当前平台。
10. 收起 AI 面板时下拉与弹窗同步关闭；重新打开后会话、搜索和面板宽度行为正常。
