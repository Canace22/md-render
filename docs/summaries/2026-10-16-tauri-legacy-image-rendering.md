# Tauri 旧工作区图片恢复显示

日期：2026-10-16

## 结果

- 从旧 Electron 工作区导入的文档重启后，仍保留「重新授权目录」入口，不再只恢复成丢失相对路径的普通副本。
- 选择原 `Documents/MdRender` 工作区后，文档中如 `../../assets/image.png` 的 Obsidian 相对图片可在 Tauri 编辑器中显示。
- 共享 `assets/` 通过独立、只读、仅媒体协议可用的会话挂载提供；普通项目命令不能用该挂载读取其他文件。

## 根因与修复

旧工作区的 Markdown 位于 `Projects/<项目>/`，图片统一位于工作区根目录 `assets/`。Tauri 迁移后每个项目单独授权，项目挂载无法访问兄弟目录 `assets/`；同时旧版快照恢复会删掉重新授权所需的相对路径上下文。

现在的处理是：

1. 快照仍可编辑，但保留重新授权状态和相对路径；已被旧版清理的节点可从稳定 ID 恢复这些信息。
2. 重新授权旧工作区时，除项目挂载外，为根目录 `assets/` 注册一个关联的只读媒体挂载。
3. 编辑器把指向共享 `assets/` 的相对路径转换成媒体 URL，保存时再恢复为原相对路径，不改写原 Markdown 语义。
4. 共享挂载 token 仅存在于当前会话，不写入工作区快照；撤销项目授权时同步撤销。

## 验证证据

- `pnpm build` 通过。
- `cargo check --manifest-path apps/editor/src-tauri/Cargo.toml` 通过。
- `cargo fmt --manifest-path apps/editor/src-tauri/Cargo.toml -- --check` 通过。
- `git diff --check` 通过。
- 根据项目规则未主动运行 Vitest 和 E2E；真实安装包的目视验收需在新版本构建后完成。

## 验收用例

| # | 场景 | 预期 |
|---|---|---|
| 1 | 旧文档使用 `../../assets/a.png` | 重新授权后图片显示 |
| 2 | 更深层文档使用 `../../../assets/a.png` | 按文档层级正确解析 |
| 3 | 项目自身目录内的相对图片 | 继续使用项目挂载，行为不变 |
| 4 | 编辑并保存含共享图片的文档 | 仍写回原相对路径，Obsidian 可继续打开 |
| 5 | 重启后旧挂载失效 | 文档可编辑，同时显示重新授权提示 |
| 6 | 已被旧版清理授权字段的快照 | 从节点 ID 和旧根目录恢复授权入口 |
| 7 | 图片路径逃逸 `assets/` | 媒体协议拒绝读取 |
| 8 | `assets/` 内存在符号链接 | 媒体协议拒绝读取 |
| 9 | 用共享挂载调用普通项目命令 | 被拒绝，只允许图片协议读取 |
| 10 | 撤销项目授权 | 项目挂载和共享图片挂载一并失效 |
