# 编辑器怎么读写本地内容（外部修改 vs 编辑器修改）

这篇讲清楚：一份本地 `.md` 文件，在「你在编辑器里改」和「别的程序在磁盘上改」这两种来源下，
数据是怎么流动、怎么判定要不要覆盖谁的。核心就一句话：**内存里的编辑内容是权威，磁盘是持久化；
两边谁该赢，用「基线」来判。**

## 三份内容，别搞混

同一个文件，脑子里要同时装着三份东西：

- **内存 buffer**：编辑器里你正在看/改的内容。本项目存的是 BlockNote 的 JSON（`node.content` /
  store 的 `markdown`），保留颜色等富文本样式。这是「当前真相」。
- **磁盘文件**：`.md` 落盘内容，是**有损 Markdown**（BlockNote → Markdown 会丢一些富文本信息）。
  写盘时若原文件有 frontmatter，会把 frontmatter 拼回去；读盘时又把 frontmatter 剥掉、只返回正文。
- **基线（`diskContentSnapshot`）**：**「我所知道的磁盘正文」**。每次自己保存成功后，把刚写下去的
  正文记成基线。它的作用只有一个 —— 回灌时用来判断「磁盘这次变了，是我干的还是外人干的」。

为什么内存是 JSON、磁盘是 Markdown 会带来一个坑：**内存 vs 磁盘没法直接判等**（格式不同）。
所以判等只发生在**同格式之间**：磁盘正文 vs 基线（都是 Markdown）。这是整套方案能成立的关键。

## 写路径：编辑器改内容

```
敲字 → onChange → 更新内存 buffer(JSON) → 防抖 400ms → 存盘
      → 存盘成功：把刚写的正文记为新基线(markLocalFileDiskSaved)
      → 主进程顺带标记「这个文件我刚写过」(忽略窗口，兜底用)
```

要点：

- **防抖**：连续输入只在停顿 400ms 后落一次盘，避免每敲一下写一次。
- **在途保存标志 `diskSavePendingFileIds`**：从「安排保存」到「落盘完成」这段时间标记为 true。
  它代表「这个文件有还没落盘的编辑」，回灌时用来保护、别被磁盘覆盖。
- **落盘成功后立刻更新基线**：这是新方案的核心动作。有了准确基线，之后监听回灌才能把「自己写的」
  认出来。

## 读路径：磁盘变了（回灌）

文件监听（`fs.watch` 递归）发现根目录下有变更 → 读盘 → 先跑冲突检测 → 再 `refreshDiskBackedProject`
把磁盘树合并进工作区。合并时对**每个文件**按下面这张表决定「保留本地 还是 采用磁盘」：

| 情况 | 判据 | 处理 |
|------|------|------|
| 有未落盘编辑 | `diskSavePendingFileIds[id]` 为真 | **保留本地**，不覆盖 |
| 自写 echo | 磁盘正文 == 基线 | **保留本地**，不重建编辑器（关键：不抢焦点） |
| 真·外部改动 | 磁盘正文 != 基线，且无在途保存 | **采用磁盘**，重载编辑器（外部改动热更新） |
| 手动「从磁盘同步」/ 冲突选「用磁盘」 | `use-disk` | **采用磁盘**，重建 |
| 冲突选「保留我的」 | `keep-local` | 保留本地 |

**为什么「采用磁盘」会重建编辑器**：BlockNote 是非受控组件，换内容要重新 `useCreateBlockNote`，
本项目用 `editorReloadToken +1` 触发。重建 = 焦点/光标丢失，所以这个动作只能发生在「确实要换成
外部内容」时，绝不能被自写 echo 触发（那正是之前失焦 bug 的根源）。

## 外部修改 方案

目标：别的程序改了文件，编辑器能感知并更新，但不能把你正在编辑的东西冲掉。

- **没在编辑这个文件**（无在途保存、基线 == 你以为的磁盘）：磁盘 != 基线 → 判为外部改动 →
  静默重载，你会看到内容更新。等同 VS Code「文件在磁盘上被修改且本地无改动 → 直接刷新」。
- **正在编辑这个文件**（有未落盘编辑）：`pending` 为真 → 先保住本地，不静默覆盖；真正的双写冲突
  交给冲突检测 / 弹窗，由你选「保留我的 / 用磁盘」。
- **只是被 touch、内容没变**：磁盘 == 基线 → 判为无变化 echo → 忽略，不做无谓重载。

## 编辑器修改 方案

目标：你自己的保存不能反过来把编辑器重置、抢焦点。

- 落盘成功 → 立刻把「刚写的正文」记为基线。
- 稍后文件监听必然回灌这次变更 → 判定时「磁盘 == 基线」→ 认成自写 echo → 保留本地、不重建。
- 这套是**内容判定**，不看事件到达时机，因此不会像旧的「保存后 900ms 忽略窗口」那样，
  因 FS 事件延迟而漏判导致失焦。旧忽略窗口保留着当**兜底**，不再是唯一防线。

## 边界与权衡

- **有损往返**：磁盘是有损 Markdown。若「外部改动」触发重载，编辑器内容会变成从 Markdown 解析回来的
  版本（原富文本样式可能丢失）。这是选择「.md 可读」必然的代价，只在真外部改动时发生。
- **基线只在本会话内存里**：应用重启后基线由磁盘读取重建（读盘时 `diskContentSnapshot = 正文`），
  不需要持久化。
- **多根监听**：`fs.watch` 是对整个项目根递归监听，回灌按文件粒度逐个判定，互不影响。
