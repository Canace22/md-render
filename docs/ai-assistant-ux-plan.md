# AI 助手交互优化方案

> 状态：方案稿（未实施） · 2026-10-05
> 范围：`AgentPanel` 及其相关入口（编辑器选区、文档工具栏、ai-proxy）

## 1. 为什么要改

AI 助手现在的问题不在于能力不够，而在于**最常用的事做起来最慢、最难找到**。

实际使用中，AI 主要用在三件事上：

| 场景 | 用户想要什么 | 结果去哪 |
|---|---|---|
| 润色 | 快速把一段话改顺，确认后写回 | 原文 |
| 找灵感 | 丢链接、文档进来，或者随便聊聊；**不直接用于创作** | 只有用户想留的时候才留 |
| 发布 | 把稿件变成各平台版本，带标题、摘要、标签 | 平台稿，然后复制出去 |

而现在的面板是按照「全能 Agent」设计的：25+ 个 skill 平铺，4 个 tab，欢迎页推的是「应用体检、生成交付物」。

## 2. 现状问题（对照代码）

### 2.1 通用问题

| # | 问题 | 位置 |
|---|---|---|
| G1 | **没有流式输出**：整轮结束才显示 `finalText`，用户只能看到「正在分析任务…」 | `agentEngine.js`、`aiClient.callChatCompletion`（IPC `ai.chat` 一次性返回） |
| G2 | 运行中按回车**没有任何反馈**：`handleSend` 遇到 `running` 直接 return，但占位符写的是「可继续编辑下一条消息」 | `AgentPanel.jsx` `handleSend` |
| G3 | AI 回复只能「复制」，没有插入 / 替换 / 重新生成 | `AgentConversation.jsx` `AgentMessage` |
| G4 | 层级太多：header 3 个按钮 + 4 个 tab；会话列表和设置是从 tab 下方推出的抽屉，打开后会挤压消息区 | `AgentPanel.jsx` |
| G5 | 出错时只追加一条「出错了：…」，没有重试按钮 | `runTurn` catch 分支 |
| G6 | 设置页使用内置 key 时，`agent-panel__builtin-hint` 是空 div；「AI 代理地址」暴露给了普通用户 | `AgentPanel.jsx` 设置区 |
| G7 | 面板宽度写死（`clamp`），不能拖动调整 | `styles.css` `.agent-panel-dock--sidebar` |

### 2.2 润色

- 欢迎页没有「润色」，它只出现在 `/` 和 `+` 菜单里；`tone`（改语气）、`subheadings`（小标题）的 `entry: []`，界面上找不到。
- **只润色选区时也要读写整篇**：`polish/SKILL.md` 要求模型先 `read_active_doc` 拿到整篇，replace 后再 `write_active_doc` 写回整篇。只改一段，却要输出整篇全文，又慢又费 token，还可能误改其他段落。
- 选区「引用到 AI」靠的是全局 mouseup/keyup 自动记录（`MarkdownEditor.jsx`），引用完还要再去面板里找按钮。

### 2.3 找灵感

- **读不了链接**：工具列表里没有读网页的工具，ai-proxy 只有 `pdf-to-docx`、`video-to-audio`。
- **外部文档放不进来**：`@` 只能选工作区里的 `.md`（`isMarkdownFile`），不支持拖入或粘贴 PDF、docx、图片。
- **AI 太想帮你写稿**：每一轮都会自动带上当前稿件（`buildTurnContext`）；写文档类的工具一直开着；欢迎语是「先理解你的工作，再动手」。随便聊两句，AI 也会往当前稿件上靠。
- 聊完没有地方留存，旧会话也找不回来（会话列表只有标题，不能搜索）。

### 2.4 发布

- 公众号版、小红书版、知乎版是三个独立的 skill（`doc-toolbar` + `slash`），每次只生成一份平台稿。
- 标题（`title-suggestions`）、审稿（`editorial-review`）是另外的 skill，要自己串起来。
- 生成结果是新文档，后续的复制、预览要手动去找。

## 3. 设计原则

1. **按场景放入口，不按能力放入口**：润色在编辑器里，灵感在面板里，发布在工具栏上。
2. **AI 能不能改文档由场景决定**：润色可以改，但要 diff 确认；灵感不能改；发布不动原稿。
3. **用户要能看到 AI 拿到了什么**：当前稿件、链接、附件都用 chip 显示，可以移除。
4. **先快再全**：流式输出、只发送必要内容，比加新功能优先。
5. 复用现有机制（diff 确认、`create_agent_artifact`、`create_content_entry`、choice cards），不另起一套。

## 4. 方案

### 4.1 基础：流式输出（解决 G1）

**原理**：模型边生成边推送片段，面板边收边显示，用户等待时就能看到内容。

- ai-proxy `/api/chat` 支持 `stream: true`，透传上游的 SSE。
- Electron：新增 `ai.chatStream` IPC，用 `webContents.send` 按片段推送；渲染进程用 `requestId` 订阅，abort 时通知主进程中断请求。
- Web 兜底：`fetch` + `ReadableStream` 读取 SSE。
- `agentEngine` 新增 `assistant_delta` 事件；遇到 tool_calls 时照常执行工具，只把文本部分流式显示。
- 面板：收到第一个 delta 时追加一条 `typing: true` 的 assistant 消息，后续只更新这条的 `text`；结束时去掉 `typing`。`message.typing` 和光标样式已经有了，可以直接用。

### 4.2 润色：在编辑器里就地完成

**交互**

```
选中一段 → 浮动工具栏出现 [✨润色] [语气▾] [精简]
        → 原段落下方出现行内对比（流式生成）
        → [✓ 接受] [✕ 放弃] [↻ 再来一版]
```

- 入口放在 `EditorFormattingToolbar`（BlockNote 的 `FormattingToolbar`），右侧加一组 AI 按钮。这个组件 Daily 编辑器也在用，所以用一个 prop 控制，只在稿件编辑器里显示 AI 按钮。
- 「语气」下拉：更口语 / 更正式 / 更简洁（复用 `tone` skill 的 prompt）。
- 整篇润色：保留文档工具栏入口，继续走现有的 diff 确认，但要接上流式输出。

**关键改动：选区不再让模型读写整篇**

- 前端记住选区对应的 block 范围和原文，**只把这一段（加上前后各一段作为上下文）发给模型**，只用于生成，不经过 agent 工具循环。
- 用一个轻量的 `runInlineRewrite({ text, context, instruction, signal, onDelta })` 直接调用 `callChatCompletion`，不带 tools。
- 用户接受后，由前端把这个 block 范围替换成新文本，进入撤销栈，Cmd+Z 可以撤销。
- 整篇模式仍然走 `polish` skill + `write_active_doc`。

**面板里的处理**：润色不进入对话流，不打扰灵感对话。

### 4.3 找灵感：面板改成「随便聊」

**会话模式**

新会话默认是「💡 聊天」模式（显示在输入框左下角，可以切换到「✏️ 写作」模式）：

| | 聊天模式 | 写作模式（现有行为） |
|---|---|---|
| 自动带上当前稿件 | 否（`@` 了才带） | 是 |
| 可用工具 | 只读：`read_url`、读附件、`search_docs`、`recall_related_docs`、`search_external_knowledge` | 全部 |
| 系统提示 | 讨论、发散、追问，不急着给成稿，不主动提议改文档 | 现有提示 |
| 回复操作 | 复制、📌 记下来 | 复制、插入、替换 |

实现：会话上加一个 `mode` 字段（`agentSlice`）；`runTurn` 根据 mode 决定 `taskContext` 和 `allowedTools`，复用现有的 `allowedTools` 白名单机制。

**资料怎么进来**

- **链接**：新增 `read_url` 工具，放在主进程或 ai-proxy，负责抓取网页并提取正文（readability）、截断长度、返回标题和来源。输入框检测到 URL 时自动显示 chip「🔗 标题」，发送前就预取内容，失败时 chip 标红并提示。
- **文件**：输入框支持拖入或粘贴 PDF、docx、txt、md、图片，统一转成文本后变成附件 chip（复用 `attachedFiles` + `buildInputWithAttachments`）。PDF 和 docx 复用现有的转换能力提取文字；图片如果模型支持视觉就直接传。
- `@` 保持现有逻辑，只选工作区文件。

**聊完留下东西（只在用户主动时）**

- 每条回复加「📌 记下来」：追加到工作区一个固定的「灵感」笔记（不存在就用 `create_content_entry` kind=material 新建），格式是：

  ```md
  ## 2026-10-05 · 会话标题
  > 记下的那段内容
  来源：链接 / 文档名
  ```

- 会话菜单加「整理这次聊天」：AI 把聊到的点子和引用的链接总结成几条，写进同一个笔记。默认不自动做。

**会话找回**

- 会话列表显示标题、日期和模式图标，支持关键词搜索（标题 + 首条消息）。
- 会话标题在第一轮结束后自动生成（截取第一条消息或让模型起一个短标题）。

### 4.4 发布：一条流程

**入口**：文档工具栏把现在三个平台按钮合并成一个「🚀 准备发布」。

**流程**

```
选平台（公众号 / 小红书 / 知乎，可多选）+ 可选「先审稿」
  → 并行生成：平台正文 + 3 个标题备选 + 摘要 + 标签
  → 结果弹窗：按平台分 tab，每块有 [复制]；公众号 tab 有 [预览排版]（复用 wechatPreview）
  → [保存为平台稿]（走 create_agent_artifact，保留来源）
```

- 每个平台复用现有 skill（`wechat-version` 等）的 prompt，再加一个结构化输出要求（JSON：title[]、summary、tags、body）。
- 审稿结果作为顶部的提示条（比如「标题偏长」「第 3 段事实缺来源」），只提示，不阻止发布。
- 不生成文件也能复制，保存是可选的，避免工作区里堆满平台稿。

### 4.5 面板结构精简（解决 G2–G7）

```
┌ 会话标题 ▾        [＋] [⚙] [✕] ┐   ← 会话列表变成标题下拉；设置改为弹窗
│                                  │
│  欢迎页 / 对话流                 │
│                                  │
├──────────────────────────────────┤
│ [📄当前稿件 ×] [🔗链接 ×] [📎文件 ×] │   ← 上下文 chip
│ ┌──────────────────────────────┐ │
│ │ 输入…                        │ │
│ │ 💡聊天▾  ＋  @        模型▾ ➤ │ │   ← 工具按钮放进输入框底栏
│ └──────────────────────────────┘ │
└──────────────────────────────────┘
```

- 去掉 4 个 tab。「上下文」由输入框上方的 chip 取代；「技能」「活动」收进 ⚙ 菜单或 `/` 列表。
- 欢迎页：删掉三个徽章。聊天模式只显示一句「丢个链接、文档进来，或者随便聊聊」，加 2–3 个示例；写作模式显示润色、标题、提纲。
- 运行中按回车：**排队**，当前这轮结束后自动发送；输入框上方显示「已排队 1 条」，可以取消。
- 出错消息加 [重试]；连接类错误再加 [打开设置]。
- 设置：修掉空的 hint；「AI 代理地址」「Base URL」收进「高级」折叠区。
- 面板左边缘加拖拽把手，宽度存到 localStorage（try/catch）。

### 4.6 skill 入口调整

只改 `agents/md-render.yaml` 里的 `entry`，不动 prompt：

| skill | 现在 | 调整后 |
|---|---|---|
| polish / tone / compress | slash, composer / 无 | slash + 选区工具栏 |
| app-diagnostics、create-deliverable | welcome | 只保留 slash |
| wechat / xiaohongshu / zhihu-version | doc-toolbar | 合并进「准备发布」 |
| outline、title-suggestions、related-docs | 分散 | 写作模式欢迎页 |

选区工具栏需要新增 entry 类型 `selection-toolbar`（`pickSkillItems` / `filterSkillsByEntry` 支持即可）。

## 5. 分期

| 阶段 | 内容 | 依赖 | 预估 |
|---|---|---|---|
| **P0** | 流式输出（4.1）+ 回车排队 + 重试按钮 | — | 中 |
| **P1** | 选区就地润色（4.2） | P0 | 中 |
| **P2** | 聊天模式 + `read_url` + 拖入文件 + 📌记下来（4.3） | P0 | 大 |
| **P3** | 准备发布流程（4.4） | — | 中 |
| **P4** | 面板精简、会话搜索、拖拽宽度、设置整理（4.5） | — | 小 |

建议顺序：P0 → P1 → P2 → P4 → P3。如果找灵感用得比润色多，可以把 P2 调到 P1 前面。

## 6. 测试 case

**流式输出**
1. 发送长问题，第一个字在 1–2 秒内出现，之后持续追加，结束后光标消失。
2. 生成过程中点停止，请求中断，已经输出的内容保留，并标注「已停止」。
3. 中途需要调用工具时，工具步骤正常显示，工具结束后继续流式输出文本。

**润色**
4. 选中一段点「润色」，只有这段被替换，其他段落内容完全不变（比较前后全文 diff）。
5. 接受后按 Cmd+Z，一次就能恢复原文。
6. 点「再来一版」得到不同的结果；点「放弃」后文档没有任何变化。

**聊天模式**
7. 打开某篇稿件，在聊天模式下问「你觉得这个话题怎么样」，请求里不含稿件正文，也不会调用 `write_active_doc`（检查 taskContext 和 allowedTools）。
8. 贴一个公众号文章链接，chip 显示文章标题，AI 的回答引用了文章里的具体内容。
9. 链接打不开（404 / 超时），chip 标红，AI 说明读取失败，不会编造内容。
10. 拖入 PDF，生成附件 chip，AI 能回答 PDF 里的内容。
11. 点「📌 记下来」，灵感追加到今日速记的「💡 笔记」分区，带会话名和来源；当前稿件不变。

**发布**
12. 勾选公众号和小红书，两个 tab 都生成了正文、标题、摘要、标签，复制的内容和显示的一致。
13. 不点保存直接关闭，工作区里不会多出文件。

**面板**
14. 运行中输入第二条并回车，显示「已排队」，第一轮结束后自动发送。
15. 断开 ai-proxy 后发送，错误消息上有 [重试] 和 [打开设置]；恢复后点重试能成功。

## 7. 不做的事

- 不做自动发布到平台（不接平台 API），只做到「复制 / 预览」。
- 聊天模式不自动把对话总结进灵感库，必须用户手动点。
- 不新增 skill 体系或新的 agent 框架，只调整入口、模式和工具白名单。
